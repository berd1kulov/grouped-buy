# Birga — запуск Mini App и Telegram-бота

## Что реализовано

Рабочая локальная демонстрация на Python 3.9+ и SQLite, без сторонних библиотек. Интерфейс: адаптивный каталог с фильтрами, карточка группы, условия участия, тестовый платеж, подтверждение предложения, отдельная оплата товара, возврат, «Мои покупки», уведомления, профиль и обращения. Изменения сохраняются в БД.

Локальный пульт демонстрации проводит группу через сбор предложений, объективный выбор минимальной цены среди трех тестовых поставщиков, подтверждение/оплату тестовых соседей, фиксацию партии и монтаж. Название Birga — рабочее, проверка товарного знака/домена не проводилась.

Бот реализует /start, /orders, /help, /support, кнопку запуска Mini App, меню, долгий опрос Telegram и очередь уведомлений с повторными попытками. Для входа Mini App сервер проверяет подпись Telegram initData и его свежесть, затем выдает HttpOnly-сессию. Токен не отправляется в браузер.

## 1. Локальный запуск

Из корня проекта:

```bash
python3 -m app.server
```

Откройте [приложение](http://127.0.0.1:8080). По умолчанию включен APP_MODE=demo; бот и токен не нужны. Это один общий демонстрационный пользователь на локальном сервере.

```bash
python3 -m unittest discover -s tests -v
python3 -m app.manage status
```

Для повторного прохождения: остановите сервер Ctrl+C, затем выполните:

```bash
python3 -m app.manage reset-demo
python3 -m app.server
```

Сброс создает резервную копию предыдущей demo-БД. Не выполняйте его при работающем сервере или боте.

## 2. Демонстрационный сценарий

1. Откройте первую группу «Прохлада для всего дома». В ней 19 явно тестовых участников.
2. Нажмите «Присоединиться», прочитайте условия и внесите тестовый платеж — станете 20-м.
3. Раскройте «Пульт демонстрации» → «Начать сбор предложений» → «Добавить тестовые предложения» → «Выбрать победителя».
4. Подтвердите предложение сами. Затем в пульте нажмите «Выполнить шаг за тестовых соседей» и «Открыть оплату».
5. Выполните свою тестовую оплату поставщику. Платеж участия отобразится возвращенным отдельно.
6. В пульте выполните оплату за тестовых соседей, затем «Зафиксировать партию».
7. Нажмите «Завершить доставку и монтаж», затем как покупатель подтвердите получение.
8. Проверьте «Мои покупки» и уведомления. Для проверки отказа/возврата используйте новую демо-БД или другую группу.

Все финансовые операции в этом сценарии — записи симулятора, без вызова Click/Payme и без реальных денег. Тестовые поставщики/товары не являются публичной офертой.

## 3. Подключение настоящего Telegram-бота

Регистрация бота в BotFather и предоставление инфраструктуры еще не выполнены. Нужны ваш собственный бот и публичный HTTPS-адрес.

1. В [BotFather](https://t.me/BotFather) создайте бота командой /newbot, задайте название и свободный username.
2. Скопируйте `.env.example` в `.env` локально. Впишите BOT_TOKEN в этот файл; не публикуйте и не присылайте его в чат.
3. Настройте публичный HTTPS-домен, который проксирует приложение на localhost:8080. Не выставляйте Python development server напрямую в Интернет. Для полноценного размещения требуется отдельно подготовить процесс-менеджер, reverse proxy, ограничения запросов, резервные копии и эксплуатацию.
4. Измените в `.env`:

```dotenv
APP_MODE=telegram
DATABASE_PATH=data/telegram.sqlite3
HOST=127.0.0.1
PORT=8080
BOT_TOKEN=токен_вашего_бота
WEBAPP_URL=https://ваш-домен
ADMIN_IDS=ваш_telegram_user_id
SUPPORT_CONTACT=контакт_поддержки
```

5. Запустите сервер и бота в отдельных терминалах:

```bash
python3 -m app.server
```

```bash
python3 -m app.bot
```

6. Напишите /start вашему боту, откройте Mini App и проверьте вход, меню и /orders. Бот устанавливает собственные команды и кнопку меню при запуске. Если у бота уже настроен webhook, запуск остановится, не изменяя его; используйте отдельного бота или осознанно перенастройте существующего.
7. При желании настройте Main Mini App в BotFather, указав тот же URL. Кнопка web_app и меню уже создаются кодом бота.

В Telegram-режиме используется отдельная пустая БД; тестовые группы не переносятся. Сейчас этот режим предназначен для проверки входа и бота: создание реальных групп и денежные операции закрыты на сервере. ADMIN_IDS зарезервирован для дальнейшего операторского доступа; полноценная рабочая админ-панель еще не реализована.

## 4. Границы текущей версии относительно ТЗ

| Область | Реализовано | Следующий этап |
|---|---|---|
| Mini App | Русский адаптивный интерфейс и основной демонстрационный цикл | Узбекская локализация, реальные карточки SKU и адресная проверка |
| Вход | Telegram HMAC, свежесть initData, серверная сессия | Ограничение частоты, MFA операторов, эксплуатационная защита |
| Группы | Тестовая модель, вместимость, цель, минимальная партия | Производственные дедлайны/worker, 15-минутные резервы, приглашения waitlist |
| Предложения | Тестовые предложения, минимальная допустимая цена | Кабинет поставщика, реальные документы, два раунда и проверка независимости |
| Платежи | Идемпотентный симулятор и полный возврат | Договор и адаптер Click/Payme, callback, неизвестные результаты, сверка |
| Оплата товара | Отдельная тестовая оплата полной суммы | Подтверждение оплаты финансовой ролью из реестра поставщика |
| Исполнение | Фиксация партии, симуляция монтажа, приемка покупателем | График, доказательства исполнения, обработка частичных возвратов |
| Поддержка | Локальные обращения по собственному заказу | Очередь оператора, SLA, ответы и эскалация |
| Бот | Команды, меню, polling и повторы уведомлений | Реальная проверка с токеном и HTTPS; контроль доставки и метрики |
| Финансы | Раздельные платежи/возвраты в SQLite | Ledger, комиссия, отчеты и бухгалтерская сверка |

Это первая исполняемая версия для проверки пользовательского пути, а не завершенная платежная платформа. Нельзя включить реальные списания простым переключателем: в коде нет реального платежного адаптера. Тестовые возвраты немедленные; это не обещание сроков реального платежного партнера.

## 5. Проверки

21 автоматический тест проверяет: полный цикл; отдельный возврат платежа участия; отмену группы с возвратом двух видов платежей; повторные запросы; конфликт ключей; согласие с условиями; минимальный объем; конкуренцию предложений; срок предложения; отказы; запрет преждевременной приемки; чужие заказы; конкуренцию за последние места; блокировку реальных операций; разделение БД; подпись, подделку и срок Telegram initData.

Проверки запускаются на временных БД и не изменяют демонстрационную базу. Полный цикл первой группы также пройден через браузер: вступление → предложение → оплата → отдельный возврат → фиксация партии → монтаж → приемка. Проверена компоновка на экране 390 × 844. Подключение к Telegram API без реального токена не проверялось. HTTP-сервер стандартной библиотеки предназначен для разработки, не является готовым production hosting.
