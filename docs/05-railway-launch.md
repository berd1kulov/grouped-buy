# Первый запуск на Railway

## Ваш первый шаг

Создайте личный аккаунт на https://railway.com. Пока достаточно попасть в панель управления: размещение проекта и оплату тарифа выполним следующим шагом. Пароль от аккаунта и данные карты остаются у вас.

Проверенные условия: Hobby — $5/месяц с включенным потреблением на $5; при большем потреблении счет увеличивается. Это не фиксированная цена любого приложения. До оплаты проверить актуальную итоговую сумму, налоги и доступные ограничения расходов.

## Что подготовлено в проекте

- Dockerfile — упаковка приложения, бота и reverse proxy Caddy.
- railway.toml — проверка /health, одна копия приложения и перезапуск при сбое.
- app/hosted.py — совместный запуск трех процессов с завершением при падении одного из них.
- deploy/Caddyfile — входящий HTTP для прокси Railway, ограничение размера запросов; внешний HTTPS обслуживает Railway.
- .dockerignore — исключает .env, локальную базу и Git из сборки. Dockerfile копирует только app, web и deploy.

Одна служба использует один постоянный Volume: так приложение и бот читают одну SQLite-базу. Нельзя запускать несколько копий или отдельные службы с независимыми копиями этой базы. Не включать у службы засыпание/serverless: бот использует постоянный опрос Telegram.

## Настройка после регистрации — проведем вместе

1. Создать проект и службу, загрузив подготовленный код через приватный репозиторий или CLI. Не загружать локальный .env и data. Доступ к репозиторию и отправку токена в настройки хостинга согласовать отдельно.
2. Прикрепить постоянный Volume с mount path /data. Это обязательное условие: обычный диск сборки не сохраняет базу при пересоздании контейнера.
3. В Variables указать APP_MODE=telegram, DATABASE_PATH=/data/birga.sqlite3, PORT=8000 и секрет BOT_TOKEN. Токен хранится только в настройках хостинга, не в коде.
4. В Networking создать адрес Railway, target port 8000. Покупать домен для теста не требуется.
5. Указать WEBAPP_URL равным выданному https://адресу. Если Railway уже предоставляет RAILWAY_PUBLIC_DOMAIN, launcher построит URL автоматически. При первоначальном отсутствии адреса запуск намеренно остановится; после настройки повторить Deploy.
6. Оставить одну реплику; отключить serverless, настроить уведомления о расходах и резервные копии Volume.
7. Проверить сборку, /health, старт бота, /start и открытие Mini App с телефона. После этого — перезапуск и проверка сохранения данных.

## Текущий статус и ограничения

Сервер в аккаунте пользователя еще не создан, размещение не выполнено и тариф не оплачен. Docker/Caddy не установлены на локальном компьютере: контейнерная сборка пока не проверена, ее необходимо проверить перед публичным запуском. Проверки Python и конфигурации выполняются локально.

Telegram-режим текущего продукта остается предварительным: подтвержденный вход и бот, пустая отдельная база, реальные деньги и локальный симулятор закрыты. Для полноценного группового теста внутри Telegram потребуется следующий этап: изолированные тестовые группы для Telegram-пользователей и операторский доступ. Простое размещение не превращает локальную демонстрацию в готовый платежный сервис.

Токен, ранее отправленный в переписку, следует заменить через BotFather перед публичным запуском. Новое значение вводится локально либо непосредственно в секретные переменные хостинга.
